二、开发原则
==================================================

1. Xanze必须是一个新的、有明确原创核心的系统，不是四套开源系统的换皮版本。

2. “集成优点”优先指：
   - 吸收产品理念
   - 复用经过许可核查的独立实现
   - 通过适配器集成
   - 在Xanze统一架构下重新实现

3. 对复制或修改的第三方代码：
   - 保留原始版权声明
   - 在 THIRD_PARTY_NOTICES.md 登记来源、路径、许可证和修改内容
   - 建立 docs/source-analysis.md 和 docs/originality.md
   - 明确区分“第三方基础”和“Xanze原创能力”

4. Xanze的原创核心必须包括：
   - 统一Application DSL
   - 表单级、节点级、流程级、应用级Vibe Coding
   - 结构化Patch而非模型直接覆盖配置
   - 修改Diff、影响分析、模拟运行、自动测试、人工确认、版本发布和回滚
   - 动态员工门户
   - 权限感知的低代码运行时
   - Agent节点和企业业务流程的统一编排
   - 数据库Schema安全变更治理

5. 所有AI生成操作必须遵循：
   AI提议 -> Schema校验 -> 语义校验 -> Diff -> 影响分析 -> 干跑/测试
   -> 人工确认 -> 创建新版本 -> 发布
   AI不得直接修改生产表、生产流程、用户权限或生产数据。

6. 不要停留在分析和文档阶段。先分析，再持续实现可运行的纵向切片。

7. 每完成一个阶段：
   - 更新 PROGRESS.md
   - 写明完成项、未完成项、验证命令、测试结果和已知边界
   - 运行相关测试
   - 不得把规划中的功能标成已完成

- 一键回滚产生新的回滚记录，不改写历史

==================================================
六、Vibe Coding能力
==================================================

必须实现四个层级：

1. 表单级Vibe Coding

例子：
“金额超过50万元时必须上传预算附件，提交后金额不可修改，
财务角色可以查看成本字段，普通员工不可见。”

AI输出结构化Form Patch，包含：

- 新增/删除/修改字段
- 校验规则
- 显隐规则
- 联动规则
- 只读规则
- 默认值
- 数据字典
- 字段权限
- 布局变化

2. 节点级Vibe Coding

例子：
“将当前节点改为流程负责人审批，48小时未处理催办，
96小时后升级给部门领导，驳回时返回填报节点。”

AI输出结构化Node Patch。

3. 流程级Vibe Coding

例子：
“质量评分低于80分退回责任人整改，80到90分由数据负责人复核，
90分以上自动通过；重大问题必须增加部门领导审批。”

AI输出Graph Patch，支持：

- add_node
- update_node
- delete_node
- add_edge
- update_edge
- delete_edge
- reconnect_edge
- update_condition

4. 应用级Vibe Coding

例子：
“生成一个数据质量问题整改系统，包含问题上报、自动分类、整改、
复核、领导审批、报表、消息提醒以及权限配置。”

AI可以生成完整应用候选版本，但仍必须经过分阶段确认：

- 数据模型确认
- 表单确认
- 流程确认
- 权限确认
- 页面确认
- 数据库迁移确认
- 发布确认

每次Vibe修改必须展示：

- 用户原始指令
- AI理解摘要
- 结构化操作
- 修改前后Diff
- 影响的页面、字段、节点、角色、数据表、运行实例和测试
- 风险等级
- 模拟路径
- 自动测试结果
- 人工确认按钮
- 取消按钮
- 回滚入口
