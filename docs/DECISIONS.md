# Xanze 架构决策

## 使用方式

本文件记录已经确认、会影响多个阶段的架构决策。临时任务和未确认想法不写入这里。

## ADR-001：平台内核不按 OA、CRM、ERP、HRM 分裂

- 状态：已接受
- 决策：统一建设身份、业务语义、关系、表单、流程、Agent、看板和治理能力。
- 原因：企业套件应共享数据、权限和运行时，避免重复建设。
- 结果：具体套件作为解决方案模板进入后期阶段。

## ADR-002：关系构建与看板生成是两个独立能力

- 状态：已接受
- 决策：AI 语义关系构建器和 AI 只读看板生成器使用独立模型、API、权限和发布流程。
- 原因：前者发现并写入 Xanze 关系元数据，后者只读取数据并生成 DashboardSpec，
  二者的风险和验收标准不同。
- 结果：阶段 2 只实现关系构建器；阶段 3 单独实现只读看板。

## ADR-003：Core 是业务写入的唯一事实来源

- 状态：已接受
- 决策：Web 和 Agent 不能直接写 OceanBase；所有关系、版本和业务写入经过 Core。
- 原因：统一执行权限、事务、幂等、校验和审计。
- 结果：Agent 不配置 OceanBase 业务账号，只返回结构化候选结果。

## ADR-004：只读源与 Xanze 关系元数据分离

- 状态：已接受
- 决策：上传文件和外部只读表不能被 Xanze 修改；确认关系写入独立关系模型。
- 原因：避免 AI 修改原始证据，同时允许平台持久化列关系和行关系。
- 结果：RecordRelation 引用数据集版本、工作表、主键或行哈希，不写回源行。

## ADR-005：候选、语义、执行和血缘分层

- 状态：已接受
- 决策：
  - RelationProposal 表示待确认候选；
  - SemanticRelation 表示确认的业务关系；
  - ValueBinding 表示可写业务对象中的执行规则；
  - RecordRelation 表示具体记录连接；
  - CellLineage 表示具体值的运行来源。
- 原因：避免把模型猜测直接当成业务规则或事实。

## ADR-006：关系发现采用确定性分析与模型解释组合

- 状态：已接受
- 决策：唯一性、公式、函数依赖、外键和匹配率由可复现算法计算；
  模型只负责结合业务上下文解释、补充和形成候选。
- 原因：纯大模型无法提供稳定的数据关系证据。
- 结果：每条候选必须包含统计证据、反例、算法版本和模型状态。

## ADR-007：模型未配置时不得伪装 AI 可用

- 状态：已接受
- 决策：未提供真实模型配置时仍可运行确定性分析，但 UI 和 API 必须返回
  `DETERMINISTIC_ONLY`，自然语言语义解释入口明确不可用。
- 原因：开发环境不能依赖密钥，但也不能用模板结果冒充 Agent。
- 结果：测试可以使用 Provider Stub 验证契约，生产路径不得偷偷回退到伪造结果。

## ADR-008：阶段 2 仅支持受控文件快照

- 状态：已接受
- 决策：阶段 2 只支持 CSV 和 XLSX 的不可变快照；数据库连接和定时刷新后置。
- 原因：先验证关系发现闭环，避免同时建设连接器平台。
- 结果：文件大小、行列数、解析时间和类型白名单必须受限，XLSX 不执行宏。

## ADR-009：关系版本不可变

- 状态：已接受
- 决策：已发布 SemanticRelation 不能原地修改；修改会创建新草稿并重新验证发布。
- 原因：关系变化会影响字段计算、记录连接、流程和分析，必须可追溯和回滚。

## ADR-010：第二阶段不建设动态表单和看板

- 状态：已接受
- 决策：阶段 2 只交付关系构建器纵向闭环。
- 原因：把关系、表单和看板同时开发容易产生多个半成品。
- 结果：动态表单进入阶段 4，只读看板进入阶段 3。

## ADR-011：看板生成结构化规格，不生成任意前端代码

- 状态：已接受
- 决策：看板 Agent 未来只能生成经过 Schema 校验的 DashboardSpec。
- 原因：任意代码不可验证、难以授权且容易产生安全风险。
- 结果：图表类型、数据查询、布局和主题来自平台支持的白名单能力。
